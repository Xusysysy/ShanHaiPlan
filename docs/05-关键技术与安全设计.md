## 1. 双 2FA 动态码体系

系统有两类动态码，**算法同构、密钥与用途不同**：

| | 客户 2FA 码（SHC1） | 入场动态码（SHE1） |
|---|---|---|
| 生成方 | 客户端（本地） | 入口大屏（本地/平板） |
| 校验方 | 员工端（本地验签）→ 再携 openid 查服务 | 客户端（本地离线验签）→ F1 二次复核 |
| 密钥 | `K_CLI`（活动级） | `K_ENT`（活动级，可按入口分 KEY） |
| 载荷 | openid + window + sig | entrance_id + window + sig |
| 窗口 | 2s 刷新 / ±2 窗（≈5s）容差 | 同左 |

### 1.1 算法规格（契约）

```
WINDOW_SEC   = 2
window(t)    = floor(unix_seconds(t) / 2)
VALID_WINDOW = 当前窗口 ±2            # 覆盖 |Δt| ≤ 5s（含 4~5s 边界带）
sig          = HMAC-SHA256(K, msg)[0..12] 的 hex（12 hex chars）
msg(SHC1)    = openid   || "|" || window
msg(SHE1)    = entrance || "|" || window
```

**参考实现（Rust / TS 各一份，双端一致性用金样本测试锁定）**：

```rust
// Rust 侧（员工端验签逻辑与服务端复核共用）
pub fn verify(code_payload: &str, k: &[u8], now_unix: u64) -> Result<String, CodeErr> {
    let parts: Vec<&str> = code_payload.split('.').collect();
    let (prefix, ident, w) = (parts[0], parts[1], parts[2].parse::<u64>().map_err(|_| CodeErr::Malformed)?);
    let sig = parts.get(3).ok_or(CodeErr::Malformed)?;
    let cur = now_unix / WINDOW_SEC as u64;
    for win in cur - 2..=cur + 2 {
        let msg = format!("{}|{}", ident, win);
        let expect = hex(&hmac_sha256(k, msg.as_bytes()))[..12];
        if constant_eq(expect.as_bytes(), sig.as_bytes()) && w / 2 == win / 2 { /* w 为窗口序号 */ }
    }
    // 任何窗口匹配 → Ok(ident)；签名全不匹配 → CodeErr::BadSig；仅窗口越界 → CodeErr::Expired
    todo!() // 完整实现见仓库 shs-crypto crate（含 128 个金样本向量）
}
```

```typescript
// 小程序侧（生成 + 本地校验入场码）
import { createHmac } from "./hmac-sha256.min.js";   // 纯 JS 实现，禁用不存在的 Node crypto
function customerCode(openid: string, k: Uint8Array, offsetMs: number): string {
  const now = Math.floor((Date.now() + offsetMs) / 1000);      // 带服务器偏移校正
  const win = Math.floor(now / 2);
  const sig = hex(hmacSha256(k, `${openid}|${win}`)).slice(0, 12);
  return `SHC1.${b32(openid)}.${win}.${sig}`;
}
```

### 1.2 时间同步（2FA 可用的前提）

| 端 | 校准方式 | 频率 |
|---|---|---|
| 服务器 ×3 | 云主机默认 chrony → 云厂商内网 NTP（高精度，不依赖现场出口） | 常驻 |
| 客户端 | 入场时 `GET F1 /api/v1/time` 采样 5 次取 RTT 最小样本 → `offset` 缓存 | 入场 + 每 10min |
| 员工端 | 激活时同上 | 激活 + 每 10min |
| 入口大屏 | 直接跑在服务器/运维机上，天然同源 | — |

- 2FA 校验一律用「本地时间 + offset」，不用系统时间裸值；
- 客户端 2FA 页面显示倒计时进度条 + 「时间已校准 ✓」，异常时提示重新校时。

### 1.3 密钥管理

| 密钥 | 用途 | 分发 | 轮换 |
|---|---|---|---|
| `K_CLI` | 客户码 | 活动配置接口下发，小程序端混淆存（代码混淆 + 拆片异或） | 每场活动更换 |
| `K_ENT` | 入场码 | 同上（客户端验签用）；大屏端配置文件持有 | 每场更换 |
| `K_STAFF_ADMIN`（Ed25519 私钥） | 员工激活码签名 | 仅 BE 持有 | 每场更换 |
| `X-Internal-Token` | 服务间 | TOML 配置 | 每场更换 |
| 员工 JWT 密钥 | BE 签发/各服务验签（HS256 共享或导出公钥） | BE ↔ F1/F2 配置 | 每场更换 |

> 威胁评估：小程序包可被逆向提取 `K_CLI`。缓解：密钥**每场更换**且作用域仅限 3–5h 活动；伪造客户码仍需 openid 才能查到订单/领纪念品，风险敞口有限并全量审计。接受残余风险（企业评审结论，见 11-风险 R-06）。

## 2. 设备指纹

### 2.1 采集字段（小程序）

```
model, system(版本), platform, benchmarkLevel, SDKVersion, version(微信版本),
screenWidth×screenHeight×pixelRatio, language, timezone(偏移), batteryLevel(可取时)
→ 归一化拼接 "k=v;..." → SHA-256 → "fp:" + hex[0..32]
```

### 2.2 使用规则

- 指纹是**风控辅助**，主键永远是 wxid（避免指纹碰撞误伤）；
- 纪念品防重领采用 `wxid UNIQUE + device_fp UNIQUE` 双约束：换微信号同设备、或换设备同微信号均被拦截；
- 风控告警：同指纹 ≥3 个 wxid → `fp_alert=1`，员工端校验接口返回 `scan_alert`，现场人工判断；
- 隐私：指纹为单向哈希，不含原始参数；不采集 IDFA/IMEI 等敏感标识。

## 3. GNSS 地理围栏

```
会场中心 CONF.center = (lat0, lng0)           # 活动前现场实测打点
半径 CONF.radius_m = 800                       # 含室内漂移余量，可配
haversine((lat,lng), center) ≤ 800m → PASS
```

- API：`wx.getLocation({ type: "gcj02" })`；连续 3 次失败 → 引导页（开定位/授权/到场地边缘重试）；
- 白名单兜底：ADMIN 下发 wxid 白名单跳过围栏（嘉宾/媒体/现场调试机）；
- 坐标**不落库**，仅记 `entry_ts + pass/fail`（NFR-S5）；
- 已知风险：室内漂移可能 >100m，800m 阈值经实测校准；过大则失去防场外下单意义，过小误伤——彩排时按实测调整（07 文档 TC-GEO-03）。

## 4. 订单可靠投递（F1 → BE，零丢失设计）

### 4.1 语义保证

| 保证 | 机制 |
|---|---|
| 不丢 | WAL append+fsync 后才算受理成功；BE ACK 前永久保留 |
| 不重（对账本） | 订单号 ULID 主键幂等；重复投递 BE 返回 `existed=true` 照常 ACK |
| 保序 | 单飞行（in-flight=1）+ 批内 `seq` 排序；BE 端 `source_f1_seq` 单调校验（乱序拒绝整批 → 触发 F1 重退避） |
| 有界延迟 | 正常 ≤2s（1s 批间隔）；断网恢复后 30s 内追平（2,000 单积压实测 <10s） |

### 4.2 状态与重试参数

```
Outbox: PENDING → INFLIGHT(batch_id) → SYNCED
重试退避: 1s, 2s, 4s, 5s, 5s...（上限 5s）
投递超时: 3s（HTTPS）；批次大小 ≤50 单 或 ≤1s 窗先到者
心跳: F1 每 5s GET BE /healthz 做连通探测，断连期跳过投递尝试（省电+减噪）
重启恢复: 扫 outbox 表 state≠SYNCED → 依序重投
```

### 4.3 打印侧补偿（BE → 员工端）

- `order.new` 带 `seq`，员工端 ACK `order.printed`；BE 45s 未 ACK → 改派同区其他在线员工并标记「补打」；
- 员工端按 `order_id` 去重（重连补发场景防重复打印）；
- 极端兜底：打印全断时 ADMIN 大屏导出待打清单，手写单号放行（08 文档 SOP-07）。

## 5. 库存一致性

### 5.1 模型

- **写**：只有 F1 扣减（下单原子扣 / ADMIN 调整 / 作废回补）；
- **读**：F2 副本（WS 推送，延迟 ≤3s）仅用于展示；**任何交易判定以 F1 内存值为准**；
- 超卖防线：①小程序预检（体验层）②F1 限购+原子扣减（真防线）③期末对账（兜底）。

## 6. 安全设计

### 6.1 威胁模型（STRIDE 摘要）

| 威胁 | 场景 | 缓解 | 残余风险 |
|---|---|---|---|
| 伪造入场（Spoofing） | 场外人员扫截图入场 | 动态码 2s 刷新 + ±5s 容差 + 离线验签；F1 复核 | 截图后 5s 内转发极难实施 |
| 篡改订单（Tampering） | 抓包改价格/数量 | TLS1.3；金额快照落库；服务端终裁 | — |
| 重放下单（Replay） | 重放下单报文刷库存 | nonce 5s 去重 + wxid 单订单约束 | — |
| 黄牛批量账号（Repudiation/Abuse） | 多微信号囤货 | 指纹风控 + 限购 + 单人单订单 + 现场实名领取 | 有组织换真机残余风险 → 现场凭小票即取即走 |
| 员工越权（EoP） | ENTRY 角色调核销接口 | JWT role scope 白名单校验（每接口声明） | — |
| 员工码外泄 | 激活码截图外传 | 一次性 + 5min 过期 + 实名绑定 | — |
| 纪念品重复领（Abuse） | 排两次队 | wxid+指纹双唯一约束 + 员工端强提示 | — |
| 服务 DoS | 公网暴露面被恶意刷接口 | 限流表（03 §7）+ 云 DDoS 基础防护 + 必要时 WAF/CC 防护 | 公网带宽成本可控（CDN 卸载后仅 API） |
| 信息泄露 | 导出数据外传 | wxid 可脱敏导出；30 天清理；介质回收 | — |

### 6.2 传输与部署安全

- 全部 HTTPS/WSS（rustls + 云证书，TLS1.3）；服务间经公网域名互调 + `X-Internal-Token`（同 VPC 可选内网优化，不改变契约）；
- 云安全组最小暴露：三 ECS 公网仅放行 443/TCP；CDN 域名仅缓存静态（`/api/*` 一律回源）；
- SSH 仅运维出口 IP + 密钥登录，禁密码；
- 备份介质（U 盘）活动结束当场带离并登记；ECS 活动后制作最终快照再释放/降配。

### 6.3 隐私合规

- 收集项：openid（登录标识）、设备指纹哈希、（不落库）坐标、员工实名（内部员工自愿绑定）；
- 最小化：坐标用完即弃；openid 导出可脱敏；活动数据 30 天销毁（NFR-S5）；
- 建议现场入口张贴「本系统仅用于义卖履约与防重复领取，数据活动后 30 天删除」公示（物料见 BOM）。
